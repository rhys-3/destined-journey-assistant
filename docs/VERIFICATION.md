# 验证说明

## 自动化覆盖

Node 测试覆盖原始楼层计数、完整回复边界、覆盖漏段、实际来源、回复版本变化、固定标签及预填充、两类 API 参数、总结自然角色发送、分段大总结、旧数据迁移、保存／显隐分步重试、停止／暂停和迟到请求取消。请求检查包括逐条角色与内容保持、不注册发送补丁、独立并发快照、按请求 ID 取消与聊天切换后的迟到结果拒绝。默认提示词另检查条目启用和角色顺序、合并资料、格式条目与正文校验对应、检查／预填充组合，以及旧参数向条目的迁移。楼层检查包含第 0 楼开局、手动显隐、消息类型筛选、自动隐藏关闭时的立即隐藏和恢复自动策略；清除日志检查运行／待处理结果与世界书记录保留。

变量替身遵循酒馆助手的对象递归合并、数组整体替换与整表替换行为。开启自动隐藏检查全部助手手动状态确实删除、其他聊天变量与原生手动隐藏保留；无总结与空聊天仍保存开启状态。另检查一次操作暂停后续总结的自动隐藏、关闭开关保留当前显隐、按聊天隔离与旧状态迁移。模拟宿主未接受写入时，校验仍须报错并阻止后续显隐操作。

批次回归覆盖三套设置持续到第 120 楼的自动触发、41 楼目标 40 时一次生成、目标 20 时均分、正文长短影响切点、完整回复与讨论缺口、保留边界，以及指定范围不受目标限制。串行读取上一批新记忆，并发受数量限制且逆序返回仍按楼层保存。失败与重新载入只恢复未完成批次，旧任务保留原范围；编辑或跳过只处理选中批次，停止取消所有活动请求并拒绝迟到写入。正文检查包含默认排除项迁移、提取后排除、带属性和嵌套标签；分页用 3000 楼检查页大小、筛选和跳转。

版本测试覆盖版本递增、加载器与安装地址同步、输入不一致时停止写入，以及标签包含构建产物、已存在标签不可移动。类型同步测试覆盖 TAR/ZIP、路径限制、链接和残缺归档拒绝。

浏览器回归使用隔离 Chrome 与模拟酒馆 API，覆盖预设双向同步、模型连接、世界书联动、条目编辑排序、配置导入导出与恢复、总结页面、入口和生命周期。界面检查包含四套主题、桌面与手机布局、透明度、后台任务提示、关闭／停止／重试、按钮锁定及草稿保留。总结弹窗另用浏览器实际鼠标与键盘事件检查命中、输入、确认和取消，覆盖 1280、390、320 像素布局，防止仅调用按钮事件而漏掉点击穿透问题。浏览器命令带超时，未收到浏览器响应不会被记成通过。

## 命令与产物

总结界面的实际点击检查还覆盖条目开关与编辑弹窗、尾部互斥、双数字楼层范围、任务日志、显隐控制、完整规则与请求预览、左下角保存反馈、酒馆全部世界书选择、删除后刷新，以及保留原有非总结条目。四套主题均检查记录、生成设置、提示词和世界书四页的桌面与手机布局。

易用性检查覆盖推荐方案、手动修改转自定义、并发数、标签回车添加与删除、标点拦截、中文分隔符粘贴以及草稿不误保存；楼层明细在 3000 楼下折叠不渲染、每页最多 30 楼、组合筛选与原文按范围读取。批次界面检查选择待处理结果、草稿保护、只保存选中批次及继续剩余工作。预设新建、保存自动关闭、删除取消／确认和配置重命名使用实际鼠标键盘检查，原生浏览器确认／输入被设为报错替身。

运行命令见 [开发指南](../CONTRIBUTING.md)。测试截图和结果写入 `.ui-review/`；GitHub Actions 提供 `verification` artifact。单文件 bundle 另存为 `assistant-bundle` artifact，供同一次工作流的后续任务提交。

`scripts/check-legacy-links.mjs` 检查旧仓库地址的版本标签、main、latest 和无版本链接，核对 HTTP 状态及内容哈希。`pnpm check:cdn` 核对助手指定版本的 CDN 内容与 Git 标签。

## 测试边界

总结浏览器组通过映射到本机的测试域名访问真实 HTTP 页面，确认 `isSecureContext` 为 false、`crypto.randomUUID` 不可用，再检查配置导入、总结生成、保存与取消以及发布产物导入；酒馆和模型接口仍使用模拟数据。

自动测试不会向真实模型发送请求，模拟酒馆接口也不能替代所有宿主时序。真实 SillyTavern 与模型接口的完整回归尚未完成。

字数界面分别从旧下限格式和仅含 `<|字数要求|>`、没有下限属性的新格式启动；后者可单独运行 `node tests/ui/test-ui.cjs --modern-length`。默认验证同时执行两条路径，检查启动迁移、三种模式、非法输入、保存回滚与控件草稿；新格式启动不得依赖运行后追加旧宏。迁移单元测试另覆盖 `min_hanzi`、`min_characters` 和受管配置 v3／v4。

场外讨论的专项浏览器检查为 `node tests/ui/test-discussion.cjs` 和 `node tests/ui/test-discussion-settings.cjs`。前者使用实际讨论 service 与原生输入区结构的模拟宿主，覆盖魔法棒入口、原生总开关同步、聊天及生成生命周期、模型切换、宏状态和 260／320／390／1280 像素布局；后者复用原配置浏览器组，覆盖无独立讨论页、原生条目编辑及自定义模型副本修改，预设写入接口为模拟。配置序列化与命名配置兼容另由 Node 检查。结果与截图写入 `.ui-review/discussion-*` 和 `configuration-test-results.json`，不代表真实手机或模型测试。

本地跨工作区核对可运行 `node scripts/check-message-processing.mjs --source <命定消息处理.js 路径>`。它从对应私有工作区读取正式 split、顺序和条件宏测试宿主，串联助手两次宏处理与 Prime 原有正文分区。覆盖 Gemini 两种尾部及其自定义副本、Claude、DeepSeek、GLM 的剧情／讨论，结合三种字数模式、文风／变量设置及两种脚本注册顺序，共 84 组。检查字数下限／上限／范围实际进入最终请求且不泄漏短宏，以及参考边界、最新输入、讨论历史包装、多模态、原生头尾及预填充保留、附加连接预填充清除、交错总结参数不变与错误标记阻止发送。报告包含源码、提示词输入、锁定上游条件宏与测试宿主哈希，写入 `.ui-review/message-processing-integration.json`。完整预设不复制到本仓库；EJS 和无关动态宏不执行，深度注入为模拟，不连接酒馆或模型。

宏检查另有 Node 回归，覆盖有效结构标签、未知及已停用的标签、短宏展开、多模态内容与递归残留。浏览器通过助手实际注册的 `CHAT_COMPLETION_PROMPT_READY` 和 `GENERATE_AFTER_DATA` 回调检查结构标签不会被误删或产生未知宏通知。讨论输出专项脚本还检查完整 XML 外壳、代码示例、结束及停止时的正文保留。

真实环境应确认：脚本作用域和旧数据可访问性、聊天切换时的世界书绑定、生成与取消、主连接和自定义 API、正文注入分区，以及移动端操作。记录真实测试时应附宿主与扩展版本、使用场景和结果，不以模拟测试结果代替。

## 按改动选择检查

自定义设定回归覆盖旧字符串与平铺列表迁移、多行保留、停用与排序、空列表优先、三套思维链读取位置、损坏包装保护，以及默认布局与自定义布局兼容。设置浏览器组使用实际鼠标和键盘检查添加、编辑、停用、排序、删除撤销、恢复默认、保存失败重试、配置导入恢复和上下文切换；组合输入事件单独模拟。四套主题分别检查桌面、390、320 像素和低高度界面，截图与结果写入 `.ui-review/setting-lists-*` 和 `setting-list-results.json`。

`pnpm verify` 自动检查工作区相对 HEAD 的已暂存、未暂存和未跟踪文件。使用 `pnpm verify -- --base <提交> --plan` 查看范围，去掉 `--plan` 执行；`--full` 强制完整验证。下表按文件职责分类，混合改动取并集；同一文件同时承担核心逻辑时使用更宽范围，不根据扩展名或改动行数猜测风险。

| 改动 | 自动检查 |
| --- | --- |
| README、维护文档 | 本地文档链接；不安装依赖、不构建、不运行浏览器和 CDN 检查 |
| 总结模块 `src/summary/` | Node 测试、构建、总结界面组（含多主题和多尺寸） |
| 全局界面样式 `src/ui/` | Node 测试、构建、主题、设置与总结界面组 |
| 预设局部行为模块 | Node 测试、构建、预设交互与设置组 |
| 类型声明或声明更新工具 | Python 更新器测试 |
| 共享状态、主入口、核心定义、总渲染、配置存储、测试、版本文件、依赖、工作流及未知路径 | 完整 Node 和浏览器回归；Windows／Linux 构建，浏览器和 Python 组只在 Linux 执行一次 |

主分支比较最近一次成功工作流以来的累计改动，PR 比较与目标分支的共同祖先。上一轮失败不会因下一次只改文档而被遗漏；缺少基线或 GitHub 查询失败时完整验证。手动运行工作流执行完整验证。工作流生成的新版 dist 不作为运行时源码变更，旧总结 dist 的修改仍触发完整兼容检查。

发布任务复用同一次验证上传的 bundle，不重复运行测试或构建。纯文档和类型更新不会提交 dist 或运行版本任务。未知风险可扩大验证范围；真实酒馆测试根据宿主行为变化安排，不能把模拟测试写成真实环境通过。
